# Smart Resource Dispatcher

Утилита для контекстной оптимизации ресурсов, очистки временных файлов, анализа памяти/файла подкачки и применения твиков Windows на **C# (.NET 11.0, `net11.0-windows`)**.

Проект разрабатывается с расчётом как на обычных пользователей (понятные объяснения «простыми словами» и оценка рисков без лишнего жаргона), так и на опытных пользователей/администраторов (технические детали параметров, приоритеты процессов, управление рабочим набором памяти и диагностика).

## Текущие возможности (ядро)

* **Очистка временных файлов (`Core/DiskCleaner.cs`)**:
  * Сканирует временную папку текущего пользователя и папку `Temp` в каталоге Windows.
  * Показывает файлы старше 24 часов, которые можно открыть с правом удаления. Занятые файлы, недоступные пути и ссылки пропускаются.
  * Удаляет файлы из предпросмотра только после подтверждения и повторной проверки. Если Windows отказала в доступе после сканирования, это показывается отдельно в результате удаления.
  * В «Очистке Temp» папки Temp выбраны по умолчанию. Миниатюры Проводника (`thumbcache_*.db`) и кэш иконок (`iconcache_*.db`) можно выбрать отдельно. Сканируются только подходящие файлы старше 24 часов непосредственно в `%LocalAppData%\Microsoft\Windows\Explorer`.
  * Предпросмотр показывает объём по выбранным категориям. Проводник не перезапускается: Windows пересоздаст удалённые кэши, а занятые файлы CoreShift пропустит.
  * Опция «Кэш шейдеров DirectX» выключена по умолчанию. Она проверяет только `%LocalAppData%\D3DSCache`, не затрагивая кэши NVIDIA и других драйверов. После удаления первые запуски игр могут подтормаживать из-за повторной компиляции шейдеров.
  * Отдельная опция «Кэш шейдеров NVIDIA» выключена по умолчанию. Она проверяет только файлы старше 24 часов в `%LocalAppData%\NVIDIA\DXCache` и `%LocalAppData%\NVIDIA\GLCache`. Другие папки NVIDIA и кэш DirectX эта опция не затрагивает.
  * Архив и очередь отчётов об ошибках Windows — две отдельные опции, выключенные по умолчанию. Предпросмотр включает файлы старше 30 дней из `%ProgramData%\Microsoft\Windows\WER\ReportArchive` или `ReportQueue`. Удаление файлов из очереди может лишить Windows возможности отправить ещё не отправленные отчёты.
  * «Кэш шрифтов (диагностика)» выключен по умолчанию. Проверяются только `FontCache*.dat` непосредственно в `%windir%\ServiceProfiles\LocalService\AppData\Local\FontCache` и отдельный файл `%windir%\System32\FNTCACHE.DAT` ([расположения кэшей](https://learn.microsoft.com/en-us/answers/questions/3860093/how-to-clear-the-windows-font-cache)). Возраст файлов не ограничен; занятые и недоступные файлы пропускаются. CoreShift не останавливает службы и не меняет права доступа.
  * Для файлов Windows Update кнопка «Открыть параметры хранилища» открывает настройки для [штатной очистки Windows](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/free-up-drive-space-in-windows). В разделе «Временные файлы» выберите «Очистка обновлений Windows», если этот пункт доступен. CoreShift не удаляет `SoftwareDistribution\Download` напрямую и не останавливает службы обновления.
* **Оптимизация памяти и процессов (`Core/MemoryOptimizer.cs`)**:
  * Сбрасывает рабочий набор (`WorkingSet` через `EmptyWorkingSet` из `psapi.dll`) у выбранного пользовательского процесса.
* **ОЗУ и файл подкачки (`Core/MemoryAndPagefileManager.cs`)**:
  * Читает сведения об ОЗУ, выделенной памяти и файлах подкачки через Win32 API и WMI.
  * Формирует рекомендации по размеру файла подкачки и поясняет логику расчёта.
* **Твики системы с пояснениями (`Core/TweaksEngine.cs`)**:
  * В «Оптимизации» доступны лимит фоновых загрузок, исключения из индексации поиска и политика игрового захвата Windows 10. Кнопки открывают штатные настройки автозагрузки и графики Windows. Диспетчер задач показывает влияние приложений на запуск.
  * В «Персонализации» доступны политики диагностики, рекламного идентификатора, подборок в поиске, недавних приложений в меню «Пуск» и центра уведомлений. CoreShift может восстановить исходное значение применённой политики.
* **Контекстные профили (`Core/ContextProfileManager.cs`)**:
  * Отслеживает активное окно и меняет приоритет выбранного приложения в фокусе, восстанавливая исходный приоритет, когда фокус меняется или профиль останавливается.
  * При наличии плана «Высокая производительность» можно включать его для выбранной игры от сети. CoreShift восстанавливает исходный план после закрытия игры, отключения питания от сети или остановки профиля.

## Стек и окружение

* **Язык и платформа**: C#, `.NET` (`net11.0-windows`)
* **Пакеты NuGet**: `System.Management` для WMI и `LibreHardwareMonitorLib` для датчиков оборудования
* **Редакторы / среда**: VS Code / Zed, PowerShell, Git

## Графический интерфейс CoreShift

CoreShift запускается с правами администратора. Команды для запуска из исходников приведены ниже.

Вкладка **«Обзор»** обновляет использование ОЗУ, лимит и пик выделенной памяти и данные файлов подкачки каждую секунду, пока окно и вкладка видны.

Вкладка **«О компьютере»** показывает модель материнской платы, версию BIOS/UEFI и характеристики каждого модуля ОЗУ, включая тип, объём, скорость и слот. При открытии вкладки CoreShift считывает доступные напряжения и тайминги SPD. Тайминги SPD описывают параметры, записанные в модулях памяти. Для некоторых датчиков нужны права администратора и драйвер PawnIO. Настроенное напряжение ОЗУ из BIOS/UEFI подписано отдельно. [LibreHardwareMonitor 0.9.6](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases/tag/v0.9.6)

Крестик сворачивает CoreShift в область уведомлений Windows. Один щелчок левой кнопкой по значку открывает окно. Чтобы завершить приложение, щёлкните по значку правой кнопкой и выберите **«Выход»**.

Начиная с версии 1.0.3 установленный CoreShift проверяет обновления при запуске и каждые 30 минут. Когда доступна новая версия, вверху окна появляется баннер **«Вышла новая версия приложения»** с кнопкой **«Установить»**.

Начиная с версии 1.0.5 основное окно закрывается перед скачиванием, а этапы обновления отображаются в отдельном окне. Во время скачивания виден процент загрузки. После установки окно прогресса закрывается, и CoreShift открывается снова.

## Запуск и сборка

Из корня репозитория проверьте версию SDK командой `dotnet --version`. Если SDK из [`global.json`](global.json) отсутствует, установите [.NET 11 SDK](https://dotnet.microsoft.com/download/dotnet/11.0). Если SDK подготовлен в `obj\verification-sdk-11`, его также можно вызвать напрямую через `.\obj\verification-sdk-11\dotnet.exe`.

Для сборки из корня репозитория выполните следующие команды.

```powershell
dotnet restore Desktop/CoreShift.Desktop.csproj --locked-mode
dotnet build Desktop/CoreShift.Desktop.csproj --no-restore
```

Для запуска из исходников выполните следующую команду из корня репозитория. Если PowerShell открыт без прав администратора, отладочная сборка CoreShift покажет запрос Windows на повышение прав.

```powershell
dotnet run --project .\Desktop\CoreShift.Desktop.csproj
```

Интерфейс по умолчанию открывается в Microsoft Edge WebView2. При отсутствии [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/#download-section) CoreShift открывает WPF-интерфейс. Для сравнения двух вариантов можно запустить WPF вручную.

```powershell
dotnet run --project .\Desktop\CoreShift.Desktop.csproj -- --native-ui
```

При запуске собранного файла используйте `CoreShift.Desktop.exe --native-ui`.

## Помощник «Шифтер»

Установщик CoreShift включает модель Qwen3-VL 2B и движок llama.cpp. Откройте Шифтера с верхней панели или через поиск `Ctrl+K`. Помощник подсказывает, где найти функции CoreShift, помогает разобраться в ошибках Windows и ведёт свободный диалог. На Windows, где требуется обновить библиотеку Microsoft Visual C++ x64, полный установщик предложит установить её из своего комплекта.

Кнопка «Прикрепить фото» принимает PNG, JPEG и BMP до 12 МБ. Скриншот можно вставить через `Ctrl+V` или перетащить файл в окно чата. Сводка Windows и комплектующих добавляется к одному сообщению по кнопке «Прикрепить сведения о ПК». История хранится в оперативной памяти до закрытия окна.

Текст и изображения обрабатываются на ПК. Движок запускается на время ответа и завершает работу после него. Для текстовых вопросов модуль изображений не загружается. Модель и модуль изображений занимают суммарно около 1,55 ГБ на диске. Мелкий текст на скриншоте лучше обрезать до области ошибки. [Модель Qwen3-VL 2B](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct-GGUF) · [Движок llama.cpp](https://github.com/ggml-org/llama.cpp)

Для постоянного запуска WPF выберите «Облегчённый интерфейс WPF» в разделе настроек «Рабочая область» и перезапустите CoreShift. Если окно скрыто в трей или свёрнуто более 20 секунд, CoreShift освобождает WebView2 и заново загружает интерфейс при открытии окна.

Для сборки `.exe` графического интерфейса выполните эту команду из корня репозитория.

```powershell
dotnet build .\Desktop\CoreShift.Desktop.csproj -c Release
```

Исполняемый файл появится в `Desktop\bin\Release\net11.0-windows\CoreShift.Desktop.exe`.

Предпросмотр очистки без удаления из консоли: `dotnet run -- clean --dry-run`.

## Выпуск обновления

Для сборки установщика Windows x64 из корня репозитория нужны .NET SDK и Inno Setup 6.6 или новее.

```powershell
.\Installer\Build-Installer.ps1 -Version 1.1.5
```

Подставьте нужную версию в `-Version`. Если опустить параметр, скрипт возьмёт версию из `Desktop/CoreShift.Desktop.csproj`. Для примера выше результатом будет `dist\CoreShift-Setup-1.1.5-x64.exe`.

Сборка полного установщика загружает файлы Шифтера в `obj\shifter-assets` и сверяет SHA-256. Параметр `-WithoutShifter` собирает установщик со встроенной справкой. Для запуска модели из сборки разработчика выполните `.\Installer\Prepare-Shifter.ps1 -Destination Desktop\bin\Release\net11.0-windows\Shifter`.

Если SDK, компилятор Inno Setup и пакеты подготовлены в локальной папке `obj`, укажите их пути явно.

```powershell
.\Installer\Build-Installer.ps1 -Version 1.1.5 `
  -DotNet '.\obj\verification-sdk-11\dotnet.exe' `
  -InnoCompiler '.\obj\installer-tools\inno-6.7.4\ISCC.exe' `
  -PackageSource @('.\obj\verification-packages', '.\obj\installer-feed')
```

Прикрепите этот `.exe` к публичному релизу в [GitHub Releases](https://github.com/MatheWwWWW/CoreShift/releases) с тегом той же версии, например `1.0.4` или `v1.0.4`, и отметьте релиз как последний. CoreShift использует имя файла и контрольную сумму SHA-256 из GitHub Releases.
