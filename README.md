# Smart Resource Dispatcher

Консольная утилита Windows для диагностики памяти, очистки временных файлов, применения обратимых настроек и смены приоритета приложения в фокусе.

## Сборка

Установите [.NET 11 SDK](https://dotnet.microsoft.com/download/dotnet/11.0) версии 11.0.100 или более свежий патч этой серии. Версия SDK задаётся в [global.json](global.json). Выполните из корня репозитория.

~~~powershell
dotnet restore --locked-mode
dotnet build --no-restore
dotnet run
~~~

## Графический интерфейс CoreShift

~~~powershell
dotnet run --project Desktop/CoreShift.Desktop.csproj
~~~

В разделе «Обзор» показаны использование ОЗУ, лимит выделенной памяти и файлы подкачки. Через боковое меню доступны сброс рабочего набора по PID, предпросмотр очистки Temp, твики Windows и профиль фокуса. Для изменения политик компьютера запустите CoreShift из терминала с правами администратора. При обычном закрытии окна CoreShift останавливает активный профиль и пытается восстановить исходный приоритет процесса.

### EXE-установщик

Установщик Windows x64 включает среду выполнения .NET Desktop. CoreShift устанавливается для текущего пользователя и появляется в меню «Пуск» и списке установленных приложений.

Для пересборки нужны .NET SDK из [global.json](global.json) и [Inno Setup 6.6 или новее](https://jrsoftware.org/inno-setup/downloads). Запустите сборку из корня проекта.

~~~powershell
.\Installer\Build-Installer.ps1 -Version 1.0.0
~~~

Сборка сохраняет `CoreShift-Setup-1.0.0-x64.exe` в папку `dist`. Для нестандартного расположения инструментов укажите параметры `-DotNet` и `-InnoCompiler` с путями к их EXE-файлам.

## Диагностика памяти

Запуск без аргументов равен команде status. Она читает данные ОЗУ и файла подкачки через WMI, выводит пиковый объём выделенной памяти с загрузки, текущий лимит и состояние политик Windows. При недоступном WMI объём ОЗУ отображается как неизвестный.

По умолчанию утилита советует оставить размер файла подкачки под управлением Windows. Для ручной настройки выводится ориентир по наблюдаемой нагрузке и учитывается режим системного дампа. Подробнее о расчёте в [документации Microsoft](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/how-to-determine-the-appropriate-page-file-size-for-64-bit-versions-of-windows).

## Очистка Temp и работа с процессами

~~~powershell
dotnet run -- clean --dry-run
dotnet run -- clean --apply
dotnet run -- memory trim 1234
~~~

Команда clean показывает оценку для пользовательской и системной папок Temp. В список попадают доступные файлы, изменённые более 24 часов назад. Занятые файлы, недоступные файлы и папки, символические ссылки и junction учитываются отдельно. Для удаления введите y после предпросмотра. Утилита повторно проверит выбранные файлы. Итог показывает логический объём удалённых файлов.

Команда memory trim вызывает EmptyWorkingSet для одного PID. Это уменьшает объём страниц процесса в физической памяти на момент вызова. Приложение может снова загрузить эти страницы при обращении к ним.

## Твики Windows

~~~powershell
dotnet run -- tweak list
dotnet run -- tweak apply notification-center
dotnet run -- tweak restore notification-center
~~~

| ID | Действие и требования |
| --- | --- |
| telemetry | Политика отключения диагностических данных. Поддерживается Windows Enterprise, Education и Server. Требует прав администратора. |
| game-dvr | Запрещает игровой захват через политику поддерживаемых настольных редакций Windows 10. Требует прав администратора. |
| notification-center | Скрывает центр уведомлений для текущего пользователя. Всплывающие уведомления продолжают появляться. Требует перезагрузки. |

При применении утилита сохраняет прежнее значение в HKCU для пользовательской политики или в HKLM для политики компьютера. Восстановление возвращает исходное значение либо удаляет параметр, если до применения он отсутствовал. Если значение изменилось извне, утилита сообщает о конфликте и сохраняет резервную копию.

## Контекстный профиль

~~~powershell
dotnet run -- profile watch notepad.exe
dotnet run -- profile watch notepad.exe below-normal
~~~

Один профиль отслеживает активное окно и меняет приоритет только у процесса выбранного приложения в фокусе. Доступные значения приоритета — above-normal (по умолчанию), normal и below-normal. При смене фокуса или остановке через Ctrl+C утилита восстанавливает исходный приоритет. Если процесс завершился, профиль продолжает ждать следующего подходящего окна. При принудительном завершении утилиты изменение действует до завершения приложения или ручного восстановления приоритета.

## Проверки

~~~powershell
dotnet run --project Tests/SmartResourceDispatcher.Checks.csproj
~~~

Проверки используют временные файлы, тестовую ветку реестра и отдельный дочерний процесс. Windows CI запускает сборку, проверки и команду status.
